# AgentKit — build AI agents whose brain you train yourself

AgentKit is a Node.js framework + CLI for building AI agents that run a model
you trained in this very repo (nanoGPT on TensorFlow.js). There is **no
external LLM API**: the brain genuinely runs on your machine (CPU by default,
`@tensorflow/tfjs-node-gpu` optional).

This is the complete tutorial, from an empty checkout to a working agent.

## 1. Install

Requires Node.js >= 18. Then:

```sh
bun install   # or npm install
```

## 2. Build a brain

An agent's "brain" is a tiny GPT checkpoint produced by this repo's trainer
(`model.js` + `train.js`). The tutorial ships a ready-made corpus of agent
transcripts in `data/tutorial/corpus.txt` (generated by
`data/tutorial/make-corpus.mjs` — feel free to rewrite it with your own
dialogues).

```sh
# 2a) tokenize the corpus (character-level, writes train.bin / val.bin / meta.json)
node data/tutorial/prepare.js

# 2b) train the brain (~1 minute on a modern CPU, writes out-demo/)
node train.js config/agent_brain.js
```

You will see the loss drop from ~4.2 (random) to under ~0.3 — the model has
memorized the small corpus. That is exactly what we want for the demo.

**Using your own brain.** Any of these will do:

- Add your own text to `data/tutorial/corpus.txt` and re-run steps 2a/2b with
  different overrides, e.g. `--max_iters=5000 --n_layer=4 --n_embd=128`.
- Train a bigger corpus the same way (`bun run prepare:openwebtext` builds the
  full OpenWebText dataset from HuggingFace parquet — it is ~17 GB and takes
  hours, but uses the identical trainer).
- Point `--out_dir` anywhere; the agent manifest references it by name.

Useful trainer knobs (pass as `--key=value`, defaults live in
`config/agent_brain.js`):

| flag | what it does |
| ---- | ------------ |
| `--max_iters` | training steps; more steps = better memory of the corpus |
| `--n_layer / n_head / n_embd / block_size` | model shape; `block_size` bounds the context (and the max prompt window) the agent can use |
| `--lr_decay_iters` | set equal to `max_iters` (cosine decay to `--min_lr`) |
| `--out_dir` | where the `ckpt.json` + `ckpt.bin` checkpoint lands |

## 3. Create an agent

```sh
node agentkit/cli.js create my-agent --template coder
```

Templates: `starter` (just talks), `coder` (shell + files + math),
`researcher` (files + web). Every agent is simply a JSON manifest in
`agents/my-agent.agent.json` — open it and edit freely:

```json
{
  "name": "my-agent",
  "description": "writes code and runs shell commands",
  "brain": {
    "type": "nano",
    "checkpoint": "out-demo",   // <- any out_dir from step 2
    "dataset": "tutorial",      // <- tokenizer came from data/tutorial
    "temperature": 0.3,         // lower = closer to memorized transcripts
    "top_k": 5,
    "max_new_tokens": 48        // <= the trained block_size
  },
  "tools": ["calc", "read_file", "write_file", "exec", "list_dir"],
  "system": "You are my-agent. ...",
  "max_turns": 4
}
```

`agentkit list` shows everything you have; `agentkit show <name>` prints a
manifest.

## 4. Run it

```sh
node agentkit/cli.js run my-agent --task "What is 3*14?"
```

The loop is: think → optionally emit a tool call → see the result → think
again (up to `max_turns`) → final answer. Interactive version:

```sh
node agentkit/cli.js chat my-agent
```

Every run/chat appends a transcript to `.agentkit/<agent>/<session>.jsonl`
(you can replay or inspect them; `--no-save` skips writing).

## 5. Tools

`agentkit tools` lists the built-ins:

| tool | behavior |
| ---- | -------- |
| `calc(expr)` | arithmetic evaluation, used by task lines like `act: calc(2+2*10)` |
| `exec(cmd)` | runs a shell command (via `sh -c`, 30s timeout) and returns stdout |
| `read_file(path)` / `write_file(path, content)` | plain filesystem text I/O |
| `list_dir(path)` | directory listing |
| `http_get(url)` | fetch a URL, return the first ~20 KB (status line included) |

### The act protocol

Brains take actions by emitting a single line:

```
act: toolName(arg, arg, ...)
```

The runtime parses those lines (they never reach the final answer), executes
each tool, and feeds back an `[observed] <result>` line before the next turn.
See `agentkit/tools.js` (`parseActLines`) if you want to extend the syntax.

### Teach the brain the protocol

Tiny models don't follow instructions from text alone — they imitate what they
have seen. The tutorial corpus is full of `act:` examples, which is why the
trained demo agent happily emits them. To make your own protocol-capable
brain, add transcripts of your own into `data/tutorial/corpus.txt` (same
`[user] / [Agent] ... act: ... [observed] ...` shape), regenerate, and
retrain. The runtime does not care how the model learned to emit the lines.

## 6. Tune quality

- Generation randomness/focus: `temperature` (lower = more literal),
  `top_k` (1 = greedy memorization).
- `max_new_tokens` must stay below the trained `block_size`; longer sequences
  are out-of-distribution for the brain.
- Coherence advice: for protocol-driven agents keep the corpus tight and
  templated; variance belongs in the *values*, not the shape, of the
  transcripts.
- The demo brain is intentionally tiny (~0.1M params, 2-layer, char-level) —
  expect toy output. Scale `n_layer/n_embd/block_size/iters` and the corpus, or
  point the same manifest at any stronger checkpoint you train, and everything
  else keeps working.

## 7. Under the hood (what each file is)

| file | role |
| ---- | ---- |
| `agentkit/cli.js` | the CLI entry (create / list / show / run / chat / tools) |
| `agentkit/agent.js` | manifest validation + the think-act loop + session store |
| `agentkit/brains.js` | brain adapters (`nano` checkpoint runtime, `mock` for tests) |
| `agentkit/tools.js` | built-in tools + `act:` protocol parser |
| `agents/*.agent.json` | your agent manifests |
| `.agentkit/` | session transcripts (gitignored) |
| `test/` | `bun run test` — loop + tools coverage, no network needed |
| `model.js` | the GPT architecture (attention, MLPs, weight tying) + AdamW + checkpoint I/O |
| `train.js` | the trainer the brains are built with |
| `data/` | corpus prep scripts (`tutorial` here; `openwebtext` for full-scale training) |

## 8. Testing

```sh
bun run test
```

Covers the act-protocol parsing, each tool, and a full agent loop with a
scripted mock brain — helpful when you add your own tools or brain types.
